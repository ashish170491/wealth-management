# Performance Tracking & Market Intelligence System

## Overview
This document describes the comprehensive signal performance tracking and market intelligence system implemented for the Intraday Trading Application.

## System Architecture

### 1. Signal Performance Tracking
Automatically tracks all signals generated by:
- **Breakout Scanner**: Consolidation breakouts from Nifty 200 stocks
- **Sector Reversal Scanner**: Sector trend reversal opportunities

#### Key Components

**SignalPerformanceEntity** (`analytics/SignalPerformanceEntity.java`)
- Database entity tracking signal lifecycle from creation to target/SL hit
- Fields:
  - `symbol`, `signalType` (BREAKOUT/SECTOR_REVERSAL)
  - `signalPrice`, `currentPrice`, `targetPrice`, `stopLossPrice`
  - `gainPercent`, `peakGainPercent` (tracks best performance)
  - `status` (ACTIVE/TARGET_HIT/STOP_LOSS_HIT/EXPIRED)
  - Timestamps: `signalDate`, `lastUpdatedAt`

**SignalPerformanceTracker** (`analytics/SignalPerformanceTracker.java`)
- Core tracking service with scheduled updates
- Methods:
  - `trackBreakoutSignal()` - Registers new breakout signals
  - `trackSectorReversalSignal()` - Registers new sector reversal signals
  - `updateActiveSignalsPerformance()` - Fetches current prices daily at 3:30 PM IST
  - `getActiveSignals()`, `getTopPerformers()`, `getWorstPerformers()` - Query methods

**SignalTrackingIntegrator** (`analytics/SignalTrackingIntegrator.java`)
- Event-driven integration component
- Listens for `BreakoutSignalCreatedEvent` and `SectorReversalSignalCreatedEvent`
- Automatically tracks signals when scanners create them (loosely coupled)

### 2. Market Intelligence System
Analyzes market news and generates actionable trading suggestions.

#### Key Components

**MarketSuggestionEntity** (`intelligence/MarketSuggestionEntity.java`)
- Stores AI-generated trading suggestions
- Fields:
  - `symbol`, `suggestionType` (EXIT_POSITION, REDUCE_POSITION, WATCHLIST_ADD, etc.)
  - `priority` (HIGH/MEDIUM/LOW)
  - `reasoning`, `newsSnippets` (supporting evidence)
  - `status` (NEW/ACKNOWLEDGED/EXPIRED)
  - `expiresAt` - Auto-expiration for time-sensitive suggestions

**ZerodhaPulseNewsService** (`intelligence/ZerodhaPulseNewsService.java`)
- Fetches market news from Zerodha Pulse aggregation platform
- Methods:
  - `fetchLatestNews()` - Gets latest market news
  - `fetchStockNews(symbol)` - Symbol-specific news
  - `fetchSectorNews(sector)` - Sector-wide news
  - `searchNews(query)` - Keyword search across news sources

**MarketIntelligenceService** (`intelligence/MarketIntelligenceService.java`)
- Analyzes news for tracked symbols using keyword matching
- Runs every 2 hours during market hours (9,11,13,15 IST)
- Generates suggestions based on:
  - **Negative keywords**: fraud, scam, penalty, loss, investigation, etc.
  - **Positive keywords**: profit, expansion, acquisition, breakthrough, etc.
  - **Sector-wide trends**: Analyzes news affecting entire sectors
  - **Market-wide events**: Policy changes, regulatory updates, economic indicators

### 3. Automated Reporting

**PerformanceReportingService** (`analytics/PerformanceReportingService.java`)
- Generates HTML-formatted email reports
- **Daily Report** (3:10 PM IST):
  - Active signals with current gain %
  - Recently closed signals (today)
  - Top 5 and worst 5 performers
  - High priority market suggestions
- **Weekly Report** (Friday 3:12 PM IST):
  - Comprehensive 30-day performance statistics
  - Win rate, average gain, target/SL hit counts
  - Top 10 performers of the week
  - All market suggestions from the week

### 4. Data Cleanup Integration

**DataCleanupScheduler** (Updated)
- Added cleanup for new entities:
  - `SignalPerformanceEntity` - Retention: 180 days (6 months)
  - `MarketSuggestionEntity` - Retention: 60 days (2 months)
- Runs daily at 2:00 AM IST to manage storage

### 5. REST API for Testing

**PerformanceTrackingController** (`api/PerformanceTrackingController.java`)
- Endpoints:
  - `GET /api/performance/signals/active` - List all active signals
  - `GET /api/performance/signals/symbol/{symbol}` - Signals for specific symbol
  - `GET /api/performance/summary` - Aggregate statistics
  - `GET /api/performance/signals/top?limit=10` - Top performers
  - `GET /api/performance/signals/worst?limit=10` - Worst performers
  - `POST /api/performance/update` - Manual trigger for performance update
  - `GET /api/performance/suggestions` - All active market suggestions
  - `GET /api/performance/suggestions/high-priority` - High priority only
  - `POST /api/performance/analyze` - Manual trigger for news analysis
  - `POST /api/performance/report/daily` - Manual trigger for daily report
  - `POST /api/performance/report/weekly` - Manual trigger for weekly report
  - `GET /api/performance/health` - System health check

## Integration Flow

### When Breakout Scanner Finds a Signal:
1. `BreakoutScannerService` saves `BreakoutSignalEntity` to database
2. Publishes `BreakoutSignalCreatedEvent` via `ApplicationEventPublisher`
3. `SignalTrackingIntegrator` listens for event asynchronously
4. Calls `SignalPerformanceTracker.trackBreakoutSignal(entity)`
5. Creates `SignalPerformanceEntity` with status=ACTIVE

### When Sector Reversal Scanner Finds a Signal:
1. `SectorReversalScheduler` saves `SectorReversalEntity` to database
2. Publishes `SectorReversalSignalCreatedEvent` via `ApplicationEventPublisher`
3. `SignalTrackingIntegrator` listens for event asynchronously
4. Calls `SignalPerformanceTracker.trackSectorReversalSignal(entity)`
5. Creates `SignalPerformanceEntity` with status=ACTIVE

### Daily Performance Update (3:30 PM IST):
1. `SignalPerformanceTracker.updateActiveSignalsPerformance()` runs
2. Fetches current market prices for all active signals
3. Calculates `gainPercent` = (currentPrice - signalPrice) / signalPrice * 100
4. Updates `peakGainPercent` if current gain exceeds previous peak
5. Checks if target or stop-loss hit:
   - **Target hit**: gainPercent >= target threshold → status=TARGET_HIT
   - **Stop-loss hit**: gainPercent <= SL threshold → status=STOP_LOSS_HIT
6. Updates `lastUpdatedAt` timestamp

### Market Intelligence Analysis (Every 2 Hours):
1. `MarketIntelligenceService.analyzeMarketConditions()` runs
2. Fetches all active signals from `SignalPerformanceRepository`
3. For each tracked symbol:
   - Fetches latest news from Zerodha Pulse
   - Analyzes news content for NEGATIVE_KEYWORDS and POSITIVE_KEYWORDS
   - Calculates relevance score based on keyword matches
4. Generates suggestions:
   - **EXIT_POSITION**: If 2+ negative news items with high relevance
   - **REDUCE_POSITION**: If 1 negative news item
   - **WATCHLIST_ADD**: If strong positive news for non-tracked symbol
5. Checks sector-wide trends for tracked symbols
6. Saves suggestions to `MarketSuggestionEntity` with priority and expiry

### Email Report Generation:
**Daily (3:10 PM IST):**
1. `PerformanceReportingService.sendDailyReport()` runs
2. Queries active signals, recently closed signals (today)
3. Fetches high-priority market suggestions
4. Generates HTML report with:
   - Performance table with color-coded gains (green/red)
   - Top 5 and worst 5 performers
   - Market suggestions with reasoning
5. Sends email to configured recipients

**Weekly (Friday 3:12 PM IST):**
1. `PerformanceReportingService.sendWeeklyReport()` runs
2. Queries all signals from last 30 days
3. Calculates aggregate statistics:
   - Total signals tracked, target/SL hit counts
   - Win rate, average gain for targets/SLs
4. Generates comprehensive HTML report
5. Includes all suggestions from the week

### Database Queries:
```sql
-- View active signals
SELECT * FROM signal_performance WHERE status = 'ACTIVE' ORDER BY gain_percent DESC;

-- View signals for specific symbol
SELECT * FROM signal_performance WHERE symbol = 'RELIANCE' ORDER BY signal_date DESC;

-- View market suggestions
SELECT * FROM market_suggestion WHERE status = 'NEW' ORDER BY priority ASC, created_at DESC;

-- Performance statistics
SELECT 
    signal_type,
    COUNT(*) as total,
    AVG(gain_percent) as avg_gain,
    SUM(CASE WHEN status = 'TARGET_HIT' THEN 1 ELSE 0 END) as targets_hit,
    SUM(CASE WHEN status = 'STOP_LOSS_HIT' THEN 1 ELSE 0 END) as sl_hit
FROM signal_performance
WHERE signal_date >= DATE_SUB(NOW(), INTERVAL 30 DAY)
GROUP BY signal_type;
```

## Key Features

### 1. Automatic Tracking
- **Zero manual intervention**: Signals automatically tracked when scanners create them
- **Event-driven design**: Loose coupling via ApplicationEventPublisher
- **Async processing**: Tracking doesn't block scanner execution

### 2. Comprehensive Performance Metrics
- **Current gain %**: Real-time performance since signal generation
- **Peak gain %**: Best performance achieved (tracks missed exits)
- **Target/SL hit detection**: Automatic status updates when thresholds reached
- **Historical tracking**: All signals retained for 180 days (configurable)

### 3. Intelligent News Analysis
- **Multi-source aggregation**: Zerodha Pulse combines 20+ financial news sources
- **Keyword-based scoring**: NEGATIVE_KEYWORDS (13) and POSITIVE_KEYWORDS (15)
- **Relevance filtering**: Only news with sufficient mentions trigger suggestions
- **Priority system**: HIGH/MEDIUM/LOW based on news count and severity
- **Auto-expiration**: Suggestions expire after 24 hours to prevent stale recommendations

### 4. Actionable Reporting
- **HTML formatted emails**: Professional, color-coded tables
- **Dual frequency**: Daily (operational) + Weekly (strategic)
- **Performance metrics**: Win rate, avg gain, target/SL ratios
- **Market context**: News snippets and reasoning for each suggestion

### 5. Production Ready
- **Data retention policies**: Automatic cleanup prevents database bloat
- **Error handling**: Graceful failures with detailed logging
- **REST API**: Full testing and monitoring capabilities
- **Health checks**: System status endpoint for monitoring tools
- **Configurable schedules**: All cron expressions in application.yml

## Troubleshooting

### Signals not being tracked:
- Check if scanners are running: Look for "BREAKOUT SCAN" or "SECTOR REVERSAL SCAN" in logs
- Verify event publishing: Search logs for "Published tracking event"
- Check database: `SELECT * FROM signal_performance ORDER BY signal_date DESC LIMIT 10`

### Performance updates not working:
- Verify scheduled job: Look for "Updating performance for X active signals" at 3:30 PM
- Check broker API: Ensure quotes API returning valid prices
- Database connection: Verify MySQL connectivity

### Email reports not sending:
- Check email configuration in application.yml
- Verify JavaMailSender is configured with valid SMTP settings
- Check logs for "Sending daily report" or "Failed to send report"

### News analysis not generating suggestions:
- Verify Zerodha Pulse API is accessible
- Check logs for "Market intelligence analysis started"
- Ensure tracked symbols have active positions (status=ACTIVE)
